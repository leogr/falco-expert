# falco-release scripts

Helper scripts for the [`falco-release`](../SKILL.md) skill, generalized from the helpers of a real release preparation. Three groups: **waiters** turn waiting into events, **checks** verify published state, **gated actions** perform one public action only on the maintainer's per-item go.

## Shared conventions

- All inputs are flags; nothing is hard-coded (no default organization, repository, version, number, date, or person). Path arguments must be absolute; no script changes directory (`git -C` is used instead).
- `--help` prints purpose, flags, exit codes, and one example, then exits 0; a bad flag or a missing required argument prints usage to stderr and exits 2.
- Every timestamp is UTC (`date -u +%FT%TZ`). The last line of every run is an uppercase token the caller can test together with the exit code.
- No inline interpreters, no encoded payloads, one `curl` per line, tokens never on a command line (anonymous registry tokens travel in a header file, the release-notes token in the environment). GitHub text (titles, bodies, comments, commit messages) is passed by file path.
- Gated scripts are a **dry run by default**; `--apply` re-checks every precondition at run time and fails closed with an `ABORT:` line. The final release of any component has no script: [`gated-tag.sh`](gated-tag.sh) accepts only candidate tag formats and refuses `--final`, `--satellite`, and `--no-release`.
- [`pin-pr.sh`](pin-pr.sh) and [`sync-pr.sh`](sync-pr.sh) prepare local commits even in dry runs. Each invocation requires a fresh, absent `--clone-dir`; existing directories and symlinks are refused without deletion. Use separate clone paths for the dry run and apply.
- Bash scripts need `gh`, `jq`, `curl`, `git`; some also `tar`, `sha256sum`, `readelf` or `file`, `helm` (optional, `SKIP` otherwise), `go` (only [`release-body-build.sh`](release-body-build.sh)). Python scripts are stdlib only. `shellcheck` was not available when these were written; `bash -n` and `python3 -m py_compile` were run on every file.
- Keep release-specific instances (bodies, items files, stored tracking copies) under `OUTPUT_DIR`, never only in the temporary directory.

Test logs from the build (read-only runs against real published objects, `--apply` only against local stubs) live under `output/2026-09-22-falco-release-skill-build/` in the falco-expert repository.

## Waiters

Read-only pollers that block until one GitHub or web event happens, then exit with a code the caller can test. They never write to GitHub and take no `--apply`. They die with the session and with a reboot: record their IDs, scripts, and timeouts in the release state file and re-arm them on resume.

Shared contract:

- `--repo` always takes the full `owner/repo`. `--max-minutes` defaults to 180, `--interval-seconds` to 60.
- Exit codes: `0` positive event, `1` negative terminal event, `2` usage error, `3` timeout, `4` persistent API error (10 consecutive failures; each transient failure is logged as `API_WARN` and the wait continues).
- Output is one line per state change (not per poll), prefixed with a UTC timestamp. The final line starts with an uppercase token (`MERGED`, `SETTLED_RED`, `TIMEOUT`, ...) followed by details; non-green items are listed just above it as `  <result> | <name> | <url>`.

## Checks

Read-only verification of published state. Every script prints one `OK|MISSING|MISMATCH|SKIP|ERROR <what> <detail>` line per item between a `START <utc>` and an `END <utc>` line, ends with a final token, and uses the exit codes `0` all checks passed, `1` at least one check failed, `2` usage, `4` a network or API error prevented a check (`ERROR` lines; the result is inconclusive, re-run). Header comments cite the workflow files the expectations come from. Nothing here writes to GitHub or to any registry.

| Script | Purpose | Key flags | Final token | Exit codes |
|--------|---------|-----------|-------------|------------|

## Gated public-action scripts

Every script below is a dry run by default; `--apply` re-checks every precondition at run time and fails closed with an `ABORT:` line on any drift. Exit codes: 0 dry run OK or applied and verified, 2 usage, 3 `ABORT:` precondition or drift, 4 `GUARD_FAIL` post-apply verification, 5 refused by policy. A successful dry run ends with `DRY_RUN_OK`; a successful apply ends with the script's `*_DONE` token. Run the dry run, show it to the maintainer, obtain the go for that exact item, then `--apply`.

| Script | Purpose | Key flags | Exit / tokens |
|---|---|---|---|
| [`tracking-body-edit.py`](tracking-body-edit.py) | Guarded edit of a tracking issue body: stored copy, snapshot, live fetch; prefix-based `--tick` (tolerant of already-ticked lines, `ALREADY_TICKED`), `--replace-line`/`--with-file`, `--insert-after`/`--from-file`; CRLF and trailing newlines stripped before comparing; self-check on changed lines only | `--repo --issue --stored --snapshot`, `--tick`, `--replace-line --with-file`, `--insert-after --from-file`, `--check-live`, `--resync`, `--apply` | 3 live differs from stored or prefix not unique; 4 `GUARD_FAIL`; `GUARD_OK` |
| [`gated-tag.sh`](gated-tag.sh) | Candidate release only (`-rcN`, component prefixes, optional libs `+driver`): branch head == target, tag and release absent, green runs/jobs and `github-actions` checks with complete pagination. Required runs must test the target or an identical tree; `--allow-no-runs` needs explicit required runs. PR-tree verification also requires a selected pull-request run at the current PR head. Always publishes with `--prerelease --latest=false`; verifies the tag target and supported release flags | `--repo --tag --target-sha --branch`, `--require-run-id` (repeatable), `--require-pr-tree-of`, `--prerelease`, `--title --notes-file`, `--allow-no-runs`, `--final`, `--apply` | 5 `REFUSED` for finals, unsupported tags, satellite/lightweight modes; `TAG_DONE` |
| [`gated-rerun.sh`](gated-rerun.sh) | Re-run failed jobs only when every failed job log (whole log, ANSI stripped) matches an infrastructure pattern and the optional health URL answers 200; bounded by `run_attempt` | `--repo --run-id --workdir`, `--pattern` (repeatable), `--health-url --health-follow`, `--max-attempts`, `--whole-run`, `--apply` | 3 `ABORT: <job> does not match an infrastructure pattern`; `RERUN_DONE` |
| [`pin-pr.sh`](pin-pr.sh) | Bump a CMake `set(NAME "value")` pin plus its checksum from two agreeing downloads, exact-line edits through [`_replace_line.py`](_replace_line.py), commit with the maintainer's identity and pre-existing sign-off, push (never force, `gh` as credential helper), open the PR, verify the PR head | `--repo --base --branch --clone-dir --workdir --file --version-var --version`, `--old-version`, `--checksum-var --archive-url --old-checksum`, `--title-file --body-file --commit-message-file`, `--author-name --author-email`, `--push-remote`, `--expect-base-sha`, `--verify-only-checksum`, `--apply` | `PR_DONE <url>` |
| [`sync-pr.sh`](sync-pr.sh) | Cumulative cherry-pick sync PR onto a release branch: picks merged source PRs in order (merge, single, rebase, or squash shape resolved through the API and patch-ids), keeps author and sign-off, sets only the committer, no `-x`, patch-id check per pick, chart changelog conflicts resolved under the release branch's unreleased section by [`_resolve_changelog.py`](_resolve_changelog.py), append to an open PR with `--existing-pr` | `--repo --release-branch --source-branch --branch --clone-dir`, `--pr` (repeatable), `--existing-pr`, `--title-file --body-file`, `--committer-name --committer-email`, `--changelog-path`, `--expect-release-sha`, `--apply` | `EMPTY_PICK` / `RESOLVED_CHANGELOG` per pick; `TREE <hash> equals_source_tree=yes/no`; `SYNC_PR_DONE <url>` |
| [`milestone-batch.sh`](milestone-batch.sh) | Classified milestone assignment: items file `<number> next|patch|none`, milestones verified to exist, every item re-read live, `/milestone <title>` posted as a Prow comment from a body file, landing verified within a bounded wait | `--repo --milestone --items-file --workdir`, `--patch-milestone`, `--allow-override`, `--wait-seconds`, `--apply` | 3 on a conflicting existing milestone; `MILESTONE_BATCH_DONE` |
| [`release-body-build.sh`](release-body-build.sh) | Build a release body locally with the release-notes tool at the target workflow pin (Falco uses the ekoops fork; libs uses leodido; explicit tool overrides remain available; token through the environment via [`_rn2md_envshim.go`](_rn2md_envshim.go), never on a command line), optional libs badge prefix or falco template substitutions, release-manager trailer; prints the `gh release edit ... --notes-file` command and never runs it (no `--apply`, editing a release body is the maintainer's step) | `--repo --milestone --tool-dir --out`, `--tool-repo --tool-ref`, `--branch`, `--tag`, `--prefix-file` / `--falco-source-dir`, `--release-manager` | `BODY_BUILT <out>` |

Helpers, invoked as files by the scripts above and never inline: [`_replace_line.py`](_replace_line.py) (CMake `set(VAR "value")` single- and multi-line forms, `--old` disambiguation for variables assigned twice, `--keep-prefix` for `SHA256=`), [`_resolve_changelog.py`](_resolve_changelog.py) (lines added by the picked commit inserted under the release branch's unreleased section, self-checked), [`_rn2md_envshim.go`](_rn2md_envshim.go) (a tiny Go wrapper copied into the release-notes tool module and built as `rn2md-env`, so the token comes from `RN2MD_TOKEN` instead of `argv`; Go is required by that script anyway to build the tool).

Regression tests: run [`../tests/test_scripts.py`](../tests/test_scripts.py) with `python3 skills/falco-release/tests/test_scripts.py --workdir "$OUTPUT_DIR/<dated-test-directory>"`. They require Bash, Git, jq and Python, replace network commands with local fixtures, and retain logs under that directory. Candidate publication is tested only against a stub.

Pin targets in the falco repository (verified against the era 0.45 refs; re-check the target branch when preparing a pin): `cmake/modules/falcosecurity-libs.cmake` (`FALCOSECURITY_LIBS_VERSION`, `FALCOSECURITY_LIBS_CHECKSUM`), `cmake/modules/driver.cmake` (`DRIVER_VERSION`, `DRIVER_CHECKSUM`), `cmake/modules/falcoctl.cmake` (`FALCOCTL_VERSION`, `FALCOCTL_HASH` twice, select with `--old-checksum`), `cmake/modules/rules.cmake` (`FALCOSECURITY_RULES_FALCO_VERSION`, `FALCOSECURITY_RULES_FALCO_CHECKSUM`), `CMakeLists.txt` (`CONTAINER_VERSION`, `CONTAINER_HASH` twice). The libs and driver version variables are also assigned to `0.0.0-local` in the same files: pass `--old-version <current pin>`. See [`references/04-upstream-components.md`](../references/04-upstream-components.md#pins-with-checksums) for the line citations.
